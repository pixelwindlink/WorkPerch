先判断：本工程是不是一个「Provider」—— 有没有能力是分发给外部工程使用、需要对方先装后用的（Skill、CLI、SDK 等）。

判断只能基于本工程的真实事实，不许靠猜：`.agents/skills/` 里有没有对外提供的能力；`package.json` / manifest 里有没有对外注册的命令或包；`docs/` 里有没有面向外部使用者的文档。

不是 Provider，到此为止，不要做任何事。

如果是 Provider，本工程面临一个问题：外部工程的责任 Agent 在装上本工程的东西之前，读不到本工程的任何内容，也就不知道该怎么装、该不该装。

所以请在 `README.md` 里补一个区块，让那个 Agent 只读 README 就够：

1. 本工程提供什么给外部工程（只写真实存在的）
2. 外部工程怎么把它装进自己的工程（确切步骤，不要写「视情况而定」）
3. 装上之后，那个工程的责任 Agent 要遵守什么规则

约束：缺证据的一律不写；不确定的分类、所有权、分发范围交给人，不猜；不复制 Skill 的完整 Contract，只做路由。
