# 发布对外接入指引

## 用途与适用场景

本 Skill 用于判断当前工程是否是一个「Provider」—— 是否把能力（Skill、CLI、SDK 等）分发给外部工程使用、需要对方先装后用 —— 并在 `README.md` 中补一段供外部工程责任 Agent 阅读的接入指引。

触发场景：外部工程无法在安装前发现本工程；责任 Agent 被问到「别的工程怎么接入我们」；本工程新增了对外提供的能力。

## 使用方式

- 只做判断和撰写 README 区块，不发布、不打包、不分发能力本身。
- 判断只依据真实事实：`.agents/skills/` 中对外提供的能力、manifest 中对外注册的命令或包、面向外部使用者的文档。
- 证据不足就不写这一节，也不编造接入路径。
- 区块回答三个问题：本工程提供什么、外部工程怎么装、装上之后要遵守什么规则。
- 以文件形式分发的 Skill，安装步骤要写明确切来源目录、目标目录与复制方式，并提示外部工程登记为 `outside`（记录来源与行为 digest），使后续版本变化可由 `SKILL_DIGEST_DRIFT` 检出。
- 区块只属于本工程自己的 `README.md`；不得把本工程的接入指引写入任何被治理工程。

## 边界

- 外部工程的责任 Agent 在安装前读不到本工程任何内容，因此 `README.md` 是唯一的交接载体。
- 不复制 canonical `SKILL.md` 的完整 Contract，只做路由。
- 分类、所有权、分发范围不明确时交给人，不猜。
- 不发布、不打包、不管理版本，也不代替外部工程完成安装。
